ENGEL-1

SORUN:

Case2-firewall.log yüklendiğinde dosyadaki ~37 satır tek bir event olarak indexlendi, ayrıca event'lerin zaman damgası log içindeki gerçek tarih yerine dosyanın yüklendiği ana atandı.

HATA MESAJI:

Açık bir hata yoktu, "1 event" sonucu ve stats sorgusunda first_seen/last_seen alanlarının upload gününü (08/27/2026) göstermesi belirtiydi.

DENENENLER:

Time Range Picker "All time" yapıldı, sorun devam etti. index=case2 sourcetype=case2:firewall | stats count ile toplam event sayısına bakıldı, 1 çıktı. Sorunun ingest aşamasında olduğu, Set Source Type ekranındaki otomatik timestamp/event break algılamasının bu formatı doğru okumadığı anlaşıldı.

ÇÖZÜM:

Index silinip yeniden oluşturuldu, dosya elle ayarlarla tekrar yüklendi: Event Breaks = Every Line, Timestamp format = %Y-%m-%dT%H:%M:%S. Preview'de her satırın ayrı event olarak doğru tarihle göründüğü doğrulanıp submit edildi.

KAYNAK:

Set Source Type ekranındaki event preview ve "timestamp = none" uyarısı.

ENGEL-2

SORUN:

Timestamp formatı doğru girilmesine rağmen (Case2-winsecurity.log), Splunk log tarihini (2026-09-14) kabul edilebilir zaman penceresi dışında sayıp reddetti.

HATA MESAJI:

"The TIME_FORMAT specified is matching timestamps (Mon Sep 14 08:29:50 2026) outside of the acceptable time window... consider adjusting MAX_DAYS_AGO and MAX_DAYS_HENCE."

DENENENLER:

Preview'deki uyarı ikonuna tıklanıp hata okundu. Format string'in doğru olduğu ama log tarihinin bugünden ~18 gün ileride olduğu için Splunk'ın varsayılan MAX_DAYS_HENCE limitine takıldığı görüldü.

ÇÖZÜM:

Advanced sekmesine MAX_DAYS_HENCE = 10000 eklendi, apply edildi. Preview'de tarih doğru göründü, uyarı kalktı.

KAYNAK:

Preview panelindeki hata tooltip'i.

ENGEL-3

SORUN:

Case2-auth.log diğer dosyalardan farklı bir zaman formatındaydı (yıl içermeyen klasik syslog stili), önceki dosyalarda kullandığım format burada çalışmadı.

HATA MESAJI:

"Could not use strptime to parse timestamp from 'Sep 14 03:00:04 app-db01 sshd[1120]: Accepted publickey for svc-backup...'"

DENENENLER:

%Y-%m-%dT%H:%M:%S formatı bu dosyaya da denendi, hata verdi. Ham log satırına bakıp gerçek formatın "Sep 14 03:00:04" (yıl yok) olduğu görüldü.

ÇÖZÜM:

Timestamp format %b %d %H:%M:%S olarak değiştirildi, Splunk yıl olarak mevcut yılı (2026) varsaydı ve tarih doğru ayrıştı.

KAYNAK:

Set Source Type ekranındaki hata mesajı ve ham log formatı.
